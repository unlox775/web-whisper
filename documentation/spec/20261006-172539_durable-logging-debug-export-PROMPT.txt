## Feature 1 — Durable per-package logging
There is already `src/modules/logging/logger.ts` that persists via `manifestService.appendLogEntry` / log sessions in IndexedDB. Extend that system; do not invent a second IndexedDB database or a parallel storage stack.

Requirements:
1. **Package-scoped loggers** for the existing modules (at least: capture, analysis, transcription, storage, settings, playback, upload, telemetry, logging/app). Each package emits under its own package id.
2. **Levels**: something like `off | error | warn | info | debug` (or equivalent low/medium/high/debug — pick clear names and stick to them). Per-package level is configurable in **Advanced settings**.
3. **Lazy payloads**: the hot API must gate on an in-memory level check BEFORE building the payload. Preferred shape:
   `logger.debug('msg', () => ({ huge: serialize(...) }))`
   or `logger.debug(() => ({ message, details }))`
   Do NOT require callers to build expensive details when the level is below threshold. Eager string-only helpers can remain for trivial messages.
4. **Durable**: logs survive tab close (IndexedDB via existing storage/manifest). Not session-memory-only.
5. **Retention**: logs count toward the same storage-limit budget as audio/other blobs. Prefer **age-based deletion** for logs (oldest first / max age), so they auto-thin under the cap without needing a separate datastore package. Integrate with `applyRetentionPolicy` (or adjacent) so one retention pass can free log bytes too. Do not purge active recording audio incorrectly while doing this.
6. **Settings UI**: Advanced settings shows each package's log level control and a **bare number for current stored log bytes** for that package (and maybe a total). Keep it compact and readable on mobile.
7. **Wire real call sites** in a few high-value paths (recording start/stop, chunk write, retention pass start/result including purged counts, snip/transcript success/fail) so the logger is actually useful — not just scaffolding.
